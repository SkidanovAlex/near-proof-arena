# Streamed commitments: the real NV final layer at the size-optimal shape [measured]

Lane `lane/pq-stream-commit`, branched from `lane/pq-recursion-sha384` at 7cdc8c90e.

## What was built

The backend change is an overlay patch on the unified backend:
`native/recursion/patches/stark-backend-stream.patch`, applied by
`native/recursion/setup_stream_deps.sh` and regenerated by `make_stream_patches.sh`. The
recursion-crate overlay `openvm-recursion-stream.patch` adds one test file, and it makes
`nv_chain` print the FINAL proof's SHA-256 and save the proof. Streaming is off unless
`NEARPROOF_STREAM_COMMIT=1` is set.

`prover/stream_pcs.rs` never materialises a Reed–Solomon codeword:

* **Sub-cosets.** Take a polynomial of length 2^n on the coset-major `c·2^L` domain, with 2^k
  rows per leaf. Set s = L − max(n, k). Each residue r mod 2^s is the coset
  `ζ^a ω_L^r ⟨ω_(L−s)⟩`. Its values come from one batched coset DFT of size 2^max(n,k) over the
  zero-padded coefficients. For extension-field rounds the DFT runs on the base-field
  coordinates. A leaf's rows share one residue, so every sub-coset holds whole leaves.
* **Hashing.** Leaves are hashed on the fly with `hash_coset`, which covers coset-as-one-message
  leaves. One radix-2 block's leaf digests are reduced by `NEARPROOF_STREAM_DROP` levels
  (default 4). Only the layers above that level are kept.
* **Queries recompute.** An opened row is evaluated directly from the coefficients by Horner at
  the domain point. The dropped subtree of a queried leaf is rebuilt from its 16 leaves. There
  is no disk spill and no mmap.
* **Where it applies.** The stacked commitment (`stacked_commit_odd`) and every WHIR round
  commitment use it.

`NEARPROOF_MEMPROF=1` prints RSS and peak RSS at each prover phase boundary.

**Tests (all pass).**
* `stark-backend/tests/stream_commit.rs` (BabyBear-Poseidon2):
  * Tree identity: roots, stored layers, opened rows, single proofs, multiproofs, including
    adjacent leaves. Covered: ×1, ×3 and ×15 domains; base and extension field; drop 0, 2, 4
    and 30.
  * Whole-proof identity at b = 2: default settings, ×15, all levers, and all levers + ×15.
* `nv::stream_tests` (SHA-384/Ext12): b = 2, all levers + ×15 + wide PoW, inner and final
  domains, k = 3 and 4, 48 B and 42 B + coset leaves. Streamed proofs equal in-memory proofs
  byte for byte at drop 0, 3 and 4 (36 of 36 cases per digest setting).
* **Full scale.** The real b = 2 final streamed (`logs/b2st-stream-final.log`) gives the same
  416,171 B and the same sha256 `e5e526a2…` as the in-memory re-run. Peak RSS falls from 64.4 GB
  to **35.5 GB**, and wall time is 50.7 min against 100 min on the same shared box.

verifies under the re-derived parent vk.

**Resources:**

**Reading.** The size-optimal final for the *measured* b = 2 chain is about 340 KB (m = 3) or
330 KB (m = 64). It is not the 299–304 KB figure, which assumes the optimised chain: O-2,
program cut, and penultimate b = 5. The model holds within 0.2 % at the shape that previously
OOMed. The same prover fits that chain's final at about 40 GB.

**Merge status.** The branch has merged `origin/lane/pq-recursion-sha384` at bfad906ec, which
brings O-2 (U-13), SHA AIR v4 and the program cut. Both overlay patches still apply cleanly on
top of the updated `stark-backend-unified.patch` and `openvm-recursion-sha384.patch`. The
measurements above use the 7cdc8c90e circuit and its A3 child. A final under O-2 or SHA v4
needs that lane's new fixed-point child, which means rerunning the roughly 3 h chain. The
streamed prover runs it unchanged with `NEARPROOF_STREAM_COMMIT=1`.

## The O-2 chain under 300 KB: A1 → A2 → A3 → FINAL, all streamed [measured, PROVISIONAL]

> **Provisional.** The e2e slice found that the NV program depends on the child proof when
> the child uses PoW (lane/pq-e2e-slice README G1). The recursion lane will change the circuit to
> fix it, and this chain will be re-run once that lands. The program-binding settings used here
> are listed below.

**Tree:** lane/pq-recursion-sha384 @ 819beab10, merged here as 6d7afa907, plus both streamed
overlays. It includes the program cut, SHA AIR v4, 49 NvAir interactions per row, and
certificate-gated O-2.

**Certificates.** `NEARPROOF_DKT_CERTS` = lane/pq-dkt-verify `calc/dkt_certs_o2.json` @
fb0efdb11 (sha256 `67f7c965…`). `NEARPROOF_DKT_EXCLUDE` = `lean/DKTCertsO2_big.keys`
(sha256 `250ac4bf…`), so only kernel-proved entries count.

**Settings.** 268 bits = 236 query bits + z = 32 wide PoW, 42-B digests, coset leaves, ×15,
every lever, m = 64. Driver: `native/recursion/run_stream_chain.sh`, with `NV_LOG_ROWS=18` and
`NV_PROG_LOG=18`.

**Shapes:**
* **Penultimate:** b = 7, log_h = 20 (n_stack 18), k = 4, k1 = 2, log_final 6. Its queries are
  [41, 35, 27, 23].
* **Final:** b = 7, log_h = 20, k = 4, k1 = 1, log_final 7. Its queries are [41, 38, 29, 23].

**Shapes tried first, and why they were dropped:**
* b8/h20 (the first suggestion) fails at commit: `two_adic_generator(28)`, beyond BabyBear's
  2-adicity of 27.
* b8/h19 fails at A2. The v4 SHA trace has 2^20 rows, which exceeds the stacked height 2^19
  (`LayoutHeightExceeded`). So a penultimate needs log_h ≥ 20, a constraint the model did not
  have.
* b7/h20 with k1 = 1 was stopped at A2 for the coordinator's k1 = 2 shape.
* A run on 3c4324e8c was stopped at A2 for 819beab10.

Their logs are in `logs/o2chain-*`.

**Soundness print.** The backend's `SoundnessCalculator` prints `FINAL_SOUNDNESS total=255.1`.
That calculator scores the queries with the Johnson per-query bits and ignores the O-2 table.
The table's query counts are set for 236 query bits plus z = 32 under the certified thresholds,
and `check_agreement` re-derives them. The calculator should be taught the table; this is not a
change in the proof.

**Program-binding settings, per level** (from `nv_chain`; no env flag changes them):

| level | `bind` (in-circuit child-program binding, `bind_child_program`) | `child_nv` | app table (level-1 program as data rows) | level public value |
|---|---|---|---|---|
| A1 | off | false | none | constant 1 |
| A2 | off | true | present (data rows) | constant 1 |
| A3 | off | true | present | constant 1 |
| FINAL | off | true | present | constant 1 |

Phase A of `nv_chain` never sets `bind`, and neither does the final. The BIND role rows (prog/2)
and the app data rows are in the trace and the cost, but the binding check itself (level flag,
ACC/ACC2 comparison against the child's opening) is not emitted. Only phase B (`L2+`) enables
it. This is the same setting as the r268 chain. A bound fixed point adds the
`bind_child_program` rows (a few thousand). The statement passthrough is active at every NV
level.

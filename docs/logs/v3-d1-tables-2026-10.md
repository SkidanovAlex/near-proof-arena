### Design decisions taken in this lane (inside P-D1-1…7; deviations from the design doc)

1. **`rcptV3D1`'s receipt index `r` stays 0-based** (design §2.2 said "starts at `m₀`"). Reason:
   `r` keys walk ids (`r`, `W_AK + r`), SHA ids and `RIDS`; with `r ≥ 8192` the account walks
   would collide with `W_AK + r'` and `W_QV`. Instead the MEM time is `r + 1 + T0`, the MPOS
   position `r + M0`, the last-row count `r + rowE + M0 = PH_N` (PH_N = all leaves, which
   `mrkV3` reads).
2. **Deposit age 14 bits** (`xb52…65`, was 13): `r + T0 − tprev` reaches `4481 + 8192`.
   `xb52` is unconstrained on the first `DEP` row in `tableQ` (bits 47…56 are used only on the
   `r1` row).
3. **`mrkV3` maxLog 20**: leaves ≤ 4096 + 4481 (design §5.2 noted it).
4. **Three relay tables** (`kib`, `plf`, `rid`): a public record element is a byte, so walk
   ids, leaf message ids and id slots (> 255, not the record index) need one relay row.
5. **Ops = every tx reaching step 3** (not only candidates), with `valid` on its own bus `SIG`
   (`cand = valid · cok`): per V3-D3A-STUDY §5 rec. 1, a later `sigV3` chip replaces the
   public `SIG` segment without touching `txV3`.
6. **Function-call / gas keys:** `verifyAndCharge` fails for every non-FullAccess key, so the
   verdict needs only `fa`; `akmV3` still decodes the whole value (decodability is a reject
   condition). Allowance bytes are never read.
7. **AIR trie keys = read keys** (candidates' signer keys, access keys of stage ≥ 1), not all
   `txKeys`: non-candidate keys' values are never read and would have no `VBYTES` provider.
   A7ᴰ¹ counts the relation's trie (all `txKeys`) ≥ the AIR's count (completeness unaffected);
   soundness extracts a witness from the AIR's records (phase 2 obligation, as D0a).
8. **Body**: the D0a body segment (positions ≥ 8, received) is kept; a new segment *sends*
   positions `8 … O0 − 1` back, so only the incoming refunds (from `O0`) are `rcptV3D1`'s.
9. A failed tx that reads its signer writes the account back unchanged (acct segments are
   written values); FullAccess keys read by a tx are always written (`akmV3` VSLOT).

Post-quantum note (coordinator, 2026-10-14, V3-D3A-STUDY §D U-5…9): the D1-N tables add no
hash table (Ed25519 and its SHA-512 are native); the new tables are `Expr`-DSL definitions,
generic in the field; the new Rust components do not hash in-AIR. Nothing here hard-codes
SHA-256 / degree 8 beyond the existing D0a stack.

### Rust: the D1 pipeline (`examples/np-udr-stark-v2/source/src/v3/d1/`)

| file | content |
|---|---|
| `ed25519.rs` | `Ed25519.verify`, the spec's operation sequence (port of the spike's faithful schedule, 7,265/7,265 nearcore vectors there); SHA-512 from `sha2` |
| `tx.rs` | `pTxD1`, `sizeOk`/`valid`, `txCost`, `decodeAccessKey` + `utf8Ok`, `encodeFullAccessKey`, `verifyAndCharge` |
| `run.rs` | native D1 run (`processTxs` → op list with stages/verdicts/memory timeline, local receipts, incoming receipts), AIR pre trie over the read keys, trie-side `Native` (writes = signer accounts, credited accounts, FullAccess keys, receivers; tx walks as extra queries); sanity: outcome root, gas, burnt vs the header |
| `prep.rs` | `PrepD1` + `preparedBytesD1` (D0a header layout, 15 descriptors, extension, payloads) |
| `tables.rs` | `txV3` (16-lane byte chains, verdict), `akmV3` (decoder FSM incl. UTF-8), `kibV3`, `plfV3`, `ridV3` traces |
| `mod.rs` | `case_inputs_d1`: the 25 `nearAirV3` generators on the D1 run (`rcptV3D1` offsets `T0/O0/TOK0` via `RcptIn.d1`, D1 `tprev`s, signer accounts in `acctV3`, `akeyV3` minus `akmV3`'s keys, `mrkV3` over all leaves with public leaf ids, `sortV3` with local ids, SHA jobs `collect::instances_d1`), `hint_d1`, a native-vs-`txV3` verdict cross-check |

`npudr v3d1prove <case> <out> --air nearAirV3D1.json [--check-only] [--dump] [--mutate-op i:ok|stage]`.
Shared-code edits are visibility (`pub(crate)`) and additive parameters with D0a defaults:
`prep_claim_with(cb, d1)`, `schedqv::derive_from`, `Native.extra_queries` (empty for D0a),
`RcptIn.d1: Option<D1Off>` (`None` for D0a; `skip_serializing_if`, so D0a JSON is unchanged).

Lean side of the differentials (`conformance/D1V3.lean`, exe `np-lean-d1-v3`): `entries` (an
instrumented replay of `processTxs` with the spec's own functions → `txV3`/`akmV3` entries) and
`prep` (the verifier's `prepD1` on the Rust hint → public tape). `conformance/VerifyV3D1.lean`
(`np-lean-verify-v3d1`): `npVerifierP challengeSpecD1a nearAirV3D1 split prepD1b`
(`D1/VerifierD1Defs.lean`). Section `run-v2.d/d1.sh`.

`txOverhead` (`PH_WOVH` = |borsh txs| + |borsh newTxs|): the transaction vectors are hint data,
not AIR records, so `sizeV3`'s `8 MiB − OVH − Σ x_t ≥ 0` must count them for `w.size` (D0a
passes 0: it has no such hint data).

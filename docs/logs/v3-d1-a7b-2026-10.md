### Milestone 1: the AIR (definitions, kernel facts)

**Design decisions** (resolving the plan's open questions; everything below is in
definitions-only modules, no `Std`):

* **Where the stub comes from (the open question).**  The walk cannot end at an unrevealed
  child without information from the parent record: only `nodeV3` holds the child's hash.  So
  table 2 becomes `nodeD1` = `nodeA7` **extended** (columns `0 … 187`, constraints and
  interactions unchanged, new ones appended, as `UnfoldA7` extends `nodeV3`): a *stub window*
  `su = 1` on the first row of
  * a child window with `rv = 0` (branch or extension child not revealed), or
  * a value window with `tv = 0` (leaf or branch value not revealed),

  sends `NMQ (τ, h)` (`h` = the window's 32 bytes = `reg 0 … 31` on its first row) and provides
  a chained `SEDGE (nid, I, z, u)` at the lookup position where `buildFor` reaches the window:
  branch child `(nid, 0, j)`, extension child `(nid, s, SYM_WILD)` (the extension's dead
  last-nibble target `(nid, s)` already exists), value `(nid, tl·s, END)`.  So the walk ends
  at a child hash (or value hash) that is **not in the store**, with no node record for it;
  the new interactions are on new buses only, so every D0a view of `nodeA7` / `nodeV3` applies
  unchanged (`tableLocal_ext`).
* **Non-membership.**  Table 6 becomes `uniqD1` = `uniqV3` extended (append-only) with a
  segment index `sidx`, a last-of-instance flag `lt` (`= st` of the next entry, `1` at the end)
  and a chained lookup `GB (sidx, τ, i, prev_i, cur_i, ft, st, lt)` per row (`prev_i` = the
  delay line's `d 31`).  A new table `nmemV3` (31) proves one `NMQ (τ, h)` per 32-row segment:
  `h` in a shift register, `GB` read row by row for one entry `s`, and one of `lo < h < hi`
  (same instance), `h < hi` (`hi` first of its instance), `hi < h` (`hi` last of its
  instance), by two byte-serial strict comparisons.  No query entries are inserted into
  `uniqV3`, so its view and every D0a store argument are untouched.
* **Unread walks in their own table.**  `walkU` (30) is a copy of `walkV3` (same columns
  `0 … 55`) for the walks of ids `≥ W_UNR = 2^23`: symbols on the new bus `UKEYNIB`, `τ = 0`,
  a fifth mode `mT` (stub: `SEDGE` with `z = sym`, or `SYM_WILD` when `mW = 1`), drained after
  like an absent terminal, and **no `FINAL`** (the `UKEYNIB` balance alone forces one walk per
  key).  The candidates' walks stay in `walkV3`, whose view and link proofs are untouched.
* **Routing.**  Table 27 becomes `kibD1`: `kibV3` with the byte `w₂` decomposed into bits; a
  record with bit 7 set (`w ≥ 2^23`) goes to `UKEYNIB`, every other to `KEYNIB` as before.  (A
  separate public segment would shift the extension offset `E0` and every P0/P2 proof.)
* **The value sink.**  An exact match at a leaf (or branch) value: the value is revealed
  (`tv = 1`, ordinary `valV3` record, counted by `valA7`, walk terminal `VAL`) or it is not in
  the store (`tv = 0`, stub window with `z = END`, terminal `mT`).  "Revealed iff the hash is
  in the store" is per window = per occurrence, so duplicates and repeated keys are handled
  once.  A value revealed only for an unread key has no reader to send its bytes on `VBYTES`:
  `uvalV3` (32) sends them (one row per byte, range-checked; `valV3` receives each byte once,
  so it can only provide bytes no other table provides).
* **`prepD1`.**  `PrepD1` gets a field `uwalks : List KeyWalk := []`; `prepD1` sets
  `uwalks := unreadWalks txs` (ids `W_UNR + 2j`, `W_UNR + 2j + 1`: signer account and access
  key of transaction `j`, every transaction).  The `PKEY` payload is
  `keyPayload (p.walks ++ p.uwalks)`.  `p.walks` keeps its meaning (the candidates' and
  credits' walks).

### Soundness fix (coordinator, standing policy): `ridV3`'s slot `l` range-checked

`ridV3` (table 29) had `act·(j − (32·l + iE)) = 0` with `l` a free column: for any `i < 32` the
field element `l = (j − i)·32⁻¹` satisfies it, so a row could send a local receipt id byte on
`RIDS (W_LOC + l, i, b)` with `i ≢ j (mod 32)` and a garbage slot (the public `PRID` framing fixes
`j` only, not the split).  Fix (append-only on `ridV3`): 12 bit columns `lb 0 … 11` (9–20,
width 21) and `act·(l − Σ lb·2^k) = 0`, so `l < 2^12` (`n_loc ≤ NT0 = 4,096`) and
`32·l + i < 2^17 < P`: `j = 32·l + i` holds as naturals and `(l, i) = (j / 32, j % 32)`.
* `RidWf` gains `lrange : e.l < 2^12` and `jnat : e.j = 32·e.l + e.i` (additive; `rid_view`
  re-proved; `lean4lean` 59 declarations, `leanchecker` rc 0);
* `nearAirV3D1_sizeMaxAligned = 7,274,345` (+11,136);
* Rust `rid_trace` writes the bits; `npudr v3d1prove --mutate-rid` (row 0 with `i + 1 mod 32`
  and the field slot `(j − i')/32`) and the d1 conformance step 6 (must be rejected).

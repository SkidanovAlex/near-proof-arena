Notes:
* **`TxVerdictStmt` is true as stated.** The two spec conditions `txV3` does not compute are
  implied by the others:
  * the strict-nonce overflow guard `kn + 1 < 2⁶⁴` follows from `N = kn + 1 ∧ N < 2⁶⁴ − 1`;
  * `10¹⁹·storage < 2¹²⁸` follows from the stake test (if `storage ≤ 770`, then
    `10¹⁹·770 < 2¹²⁸`, a closed `decide`).
* **`PrepTxNativeStmt`.** The honest verdict bytes are:
  * `0` when there is no state read or the signer is absent;
  * `1` when the access key is absent;
  * `2` when `verifyAndCharge` fails;
  * `6` on success.

  `prepTx_step` is stated "∃ bytes, ∀ acc rest, Sim acc st → …", so the bytes depend only on
  the spec state. That is what makes the run induction go through.
* **Statement correction (candidate side).**
  * The phase-1 `ExtractD1Stmt` and `CompleteD1Stmt` are stated on the tape
    `preparedBytesD1 p 0`, but the verifier uses `preparedBytesD1 p (txOverhead h)`. With
    overhead 0, the `w.size` check does not count the hint's transaction vectors, which the
    extracted witness carries. So the overhead-0 soundness statement is presumably false.
  * New siblings `ExtractD1StmtT` and `CompleteD1StmtT` are stated on the verifier's tape;
    `CompleteD1StmtT` adds `headerOk` as D0a's `RenderV3Stmt` does.
  * The originals are unchanged. The `prepD1b` docstring ("`· 0`") disagrees with its code;
    the code is the verifier.
* Risk R-2 (A7ᴰ¹ over unread transaction keys) analysed: `partialTrie` never fails and
  reveals only store nodes on key paths, so it is likely benign. The obligation is in F1.
  See the plan, §5.

### Milestone 2: V2, the `txV3` view (proved)

**`tx_view : TxViewStmt`** (`Extract/TxView.lean` statement, `Extract/TxProof.lean`, `Extract/Tx/*`;
15 modules, 2,190 lines).

Each 16-row op gives a `TxE`:
* the op constants;
* 16 lanes (`g, N, Bd, C, amt, lk, st, mo, kn, nk`).

`TxOpWf` collects these facts:
* the flag algebra: `stage = s1 + s2`, `s2 ⇒ s1`, `cand = valid·cok`, a debit walk only for a
  candidate, credit ⇒ `s1 ∧ ¬s2`;
* the gates `fW`, `fK`, `wr`;
* per lane: `g ≡ 16·op + j`, `kn = 0` on lanes ≥ 8, and the unwritten / written values;
* the memory times `tp + d ≡ op` with `d < 2¹⁴`;
* under byte inputs (`TxE.Arith`):
  * a debit's `ok = 1` iff `s2 ∧ fa ∧ kn < N ∧ (strict ⇒ N = kn + 1) ∧ N < Bd ∧ C ≤ A ∧
    A − C + L < 2¹²⁸ ∧ (10¹⁹·st mod 2¹²⁸ ≤ A − C + L ∨ st ≤ 770)`, and the written amount is
    `A − C`;
  * a credit writes `A + C < 2¹²⁸ − 1` with `A + C + L < 2¹²⁸` and the stake.

The traffic is exact on `TXP`, `SIG`, `FINAL`, `MEM` and `AKMEM`.

Proof structure:
* `Tx.Rows`: the segments are exactly 16 rows (`segInfo`).
* `Tx.Lane`: `OpAt`, `eval_bitsN` (next-row bit groups).
* `Tx.ChainN/C/Q/D/Z`: each byte chain lane-by-lane, then `RcptProof.chainC`:
  * the borrow chains `N` and `B` share one generic lemma (`laneSub`);
  * the delay line `dl_val` turns the `Q` convolution into `RcptProof.convS`, so
    `q = 10¹⁹·st mod 2¹²⁸` via the D0a lemma `convS_id`;
  * `zN_iff` and `msum_val` cover the zero test and the credit sum.
* `Tx.Arith`: pure `Nat` lemmas over an abstract modulus `M` (no big literal against free
  variables). The carries are case-split.
* `Tx.Verdict`: the products of boolean cells on lane 15.
* `Tx.Flags`, `Tx.OpWf`: the entry.
* `Tx.RowT`, `Tx.SegT`: the traffic.

### Milestone 4: V3, the `akmV3` view (proved)

**`akm_view : AkmViewStmt`** (`Extract/AkmView.lean` statement, `Extract/AkmProof.lean`,
`Extract/Akm/*`; 15 modules, 2,656 lines, Σ ≈ 22 s single-core, max `Akm.Decode` 3.4 s).

Each value segment gives an `AkmE`: `vid`, `fa = t₁`, `tlast`, `U`, the bytes and the 8 post-nonce
bytes. `AkmSegWf` states:
* `decodeAccessKey (bytes) = some k`;
* `k.nonce` = `leNat` of the first 8 bytes;
* `k.perm = FullAccess ⇔ fa = 1`;
* FullAccess ⇒ the value is the 9 bytes `nonce ‖ 1`;
* non-FullAccess ⇒ `pb` = the nonce bytes (never written).

Traffic is exact on VBYTES, AKMEM (offsets 0…7), VSLOT, BYTES (VPOST), AKC.

Proof structure:
* `Akm.Rows` / `Row`: segments, the one-hot state, `fe = [lastE = 0]`, the in-field step.
* `Akm.Field`: `field` (a fixed field of length `L + 1`), `body` (a string body of `R`
  bytes), `u32field` (high byte 0, `acc` = value, `zA` = zero test).
* `Akm.Utf8Abs`: `utf8_rows`, a pure lemma. The class sequence with a field-valued pending
  count gives `utf8Ok`. A stray continuation is excluded by `neg_dead`: the count would stay
  "negative" until the end, where `ucn = 0` is required.
* `Akm.Utf8Row` / `Utf8Body`: the row classes ⇒ byte ranges, and the second-byte flags after
  E0/ED/F0/F4. Together: `body_utf8`.
* `Akm.Parse`: the borsh readers on a byte window (`takeT = takeN`, `pU*_win`, `pString_win`).
* `Akm.Events`, `Str`, `Methods`, `Decode`: the grammar walk, ending in `akm_decode`:
  * a string (`str`), carrying the method counter and the "no nonce state" facts;
  * receiver → count → method names (`rcv_to_count`, `methods` by induction on the count,
    `vecMethods`);
  * the option / allowance (`fcPerm`), the gas-key info (`gki`), and the tag cases 0/1/2/3.
* `Akm.Traffic` / `Lane`: the per-row traffic. `AkmProof`: the view.

### V4 assessment (decision requested; plan §5 R-4)

* Measured: D0a's receipt-view closure (`Assembly.RcptViewV3`) has 1,331 modules. **228 of
  them (22,454 lines)** mention the receipt table directly and carry
  `hL : TableLocal RcptV3.table`, so the re-proof is a ≥ 22 k-line copy. That is over the 15 k
  threshold.
* Trace transport is impossible:
  * `tok` is a byte-decomposed register;
  * the deposit-age window is 13 bits in `tableQ` vs 14 bits needed.
* The verbatim-`tableQ` fallback breaks on the memory ordering. Transactions must write
  accounts before the receipts' times `r + 1`, and the 13-bit age window forbids negative
  times. A bridge table is needed: a `MEMT` domain for the transaction ops, with
  per-account uniqueness. That is a larger AIR/prover change than "a small prefix table".
* Two options went to the coordinator:
  * (a) copy-and-modify on the current AIR (recommended);
  * (b) the bridge redesign.

  V4 is held until the coordinator decides.

### Milestone 5: V4, the `rcptV3D1` view (proved; checkpoint 4)

**`RcptD1.rcptD1_view : RcptD1ViewStmt`** and `rcptV3D1_view_nearAir` (`D1/R/View.lean`):

```
TableLocal tableQD1 tr t pub → ExtOk pub → ReceiptPublicRanges pub →
(∀ m, 0 < tableBusCount tableQD1.interactions tr t pub B_MEM false m → (m.getD 1 0).toNat ≤ 2^25) →
∃ ls, RcptV3WfD1 pub ls ∧ TableTraffic tableQD1.interactions tr t pub (rcptTraffic3D1 pub ls) ∧
      ∀ x ∈ flatR ls, x.q < 128
```

* `RcptV3WfD1` / `rcptTraffic3D1` (`D1/R/ViewDefs.lean`, definitions only) are D0a's
  `RcptV3Wf` / `rcptTraffic3` with the D1 offsets:
  * first token value `TOK0`;
  * `|receipts| + M0 = PH_N`;
  * refund bodies from `O0` (`bOffsG`);
  * each receipt's `RcptE.Wf` at index `r + T0` (so `tprev ≤ r + T0`);
  * `MEM` writes at `r + 1 + T0`, `MPOS` leaves at `r + M0`.

  With `M0 = T0 = TOK0 = 0`, `O0 = 8` they are D0a's.
* `ExtOk pub`: the extension `M0, T0, O0, TOK0` consists of bytes, with `M0, T0 < 2^24` and
  `O0 < 2^30` (no field wrap; P ≈ 2^31). The MEM version bound `≤ 2^25` replaces D0a's in-view
  `mem_send_sources` argument, because in D1 `txV3` also writes `MEM`. **Both are L1
  obligations**: `ExtOk` from the prepared tape (P0), the version bound from the global `MEM`
  balance (`acctV3` writes at 0, `txV3` at its op times, `rcptV3D1` at `r + 1 + T0`).
* `#print axioms`: `[propext, Classical.choice, Quot.sound]`.

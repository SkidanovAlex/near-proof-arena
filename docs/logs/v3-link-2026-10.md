### Finding: `nearAirV3` does not enforce A7 or A10 (soundness gap)

`GoodV3` (hence `factorSound` → `checkD0a B0`) contains two witness-level RelD0a conjuncts
that no `nearAirV3` constraint enforces:

* **A7** `unfoldedBytes : unfoldBytes cb w ≤ B0 = 2,000,000`.  No table mentions `B0`.  The
  only byte caps are `sizeV3` (`x0 + x1 ≤ 3,000,000` on *deduplicated* node/value record
  bytes — checkD0's `w.size`, not A7 — and `≤ 8 MiB` on the witness) and the row caps
  (`nodeV3 ≤ 2^22` rows, the SHA instances `≤ 2^22`).  A chunk whose unfolded read set plus
  post diff is in `(2,000,000, ~3,000,000]` satisfies every AIR constraint (the heights fit),
  but `a7 B0` fails for every witness (the unfolded tries are fixed by the claim's roots up to
  a SHA collision).  So `ExtractV3Stmt` (at `B0`) is not provable from the current AIR.
* **A10** `pathDepth : every used source path ≤ Dp0 = 32 items`.  `Rcpt/Tables/Srcp.lean`
  says so itself: "The AIR does not constrain the path length".  Counterexample sketch: a
  claim whose (single) source chunk commits `prevOutgoingReceiptsRoot :=
  rootFromPath leaf path` for an adversarial 33-item `path` (computed forwards, no preimage
  needed); one list needs `33 + 64·33 = 2145 < 2^22` srcp rows; the AIR accepts, and no
  witness satisfies `a10` without a SHA collision.

Either the AIR must enforce both (e.g. A10: a per-list path-item counter in `srcpV3` with
`Dp0 − depth` range-checked; A7: the node/value tables send the unfolded pre bytes incl.
duplicate occurrences plus the post diff bytes on a new `SIZE` tag, `sizeV3` checks
`B0 − x ≥ 0` in 24 bits), or the soundness target must drop them (spec/challenge decision).
Both are outside this lane (AIR frozen, spec pinned): **reported to the lead, not changed.**
A9 (`chachaWords ≤ W0 = 770,000`): plausibly implied by the `chachaV3` height (`2^21` rows at
86 rows per 16-word block hold `< 390,000` words) if every drawn word is a distinct `chachaV3`
message; not yet checked.

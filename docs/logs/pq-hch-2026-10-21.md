## What the estimate missed

1. `HostTraceOK` (`Main/ExecHost.lean:249`) was used by `host_part_ch_recv_active` /
   `host_part_ch_send_active` but had **no derivation**.  What existed was
   `host_row_inactive_emits_nothing` (inactive ⇒ `rowCons`/`rowProd` empty).  `HostTraceOK`
   quantifies over the raw counts (`pf j = 0` for `j < nArgs`, `nres = 0`), so the existing theorem
   could not be used to build it without a detour.  Fixed by factoring the body into
   `host_row_inactive_counts` (raw counts) and rebuilding `host_row_inactive_emits_nothing` on top of
   it (statement unchanged), then `host_trace_ok : Holds … → HostTraceOK …`.
2. The CH bus is genuinely asymmetric.  `msgs_ch` (`Main/Exec.lean:496`) puts:

   * true: `initRaw ++ (globRaw ++ (budRaw ++ (act ++ memRaw)))`
   * false: `(((resRaw? ++ finRaw) ++ act) ++ drainRaw)`

   so the HOST block appended by `msgs_ch_host` lands *after* `memRaw` on the true side but *after*
   `drainRaw` on the false side, while `actListHost` needs it adjacent to the instruction rows on
   both.  That is one `perm_mid` swap per side, not a `flatMap` congruence.

## Dead ends (do not repeat)

* `rw` on `List.map decMsg` inside a nested `++` tree fails: `List.map_append` must be applied
  repeatedly *before* the `part Host.table` rewrite is visible.  Do
  `rw [mh1]; simp only [List.map_append]; rw [mc1]; simp only [List.map_append, List.map_flatMap]`.
* `simpa only [List.append_assoc] using perm` often does not close when the goal is stated with
  explicit right-nesting: prove the two shapes equal as `= ` equations and `rw` them, or state the
  lemma in the exact shape needed.
* `List.perm_append_comm` needs named args (`l₁`/`l₂`) in this Lean version.
* `set x : T := …` is not available in this toolchain's tactic set (unknown tactic); use explicit
  `have`/`show` or general lemmas instead.

# Lane `lane/v3-prune` — certificate import-closure pruning, log

Worktree `/data/illia/nearproof-wt/v3-prune`, branch `lane/v3-prune`, from main `14ce4cde`.
Goal: shrink the import closure of the D0a certificate (`nearV3_admission_final`, packaged as
`NpUdrStarkV2.certificate`) without deleting code and without changing any statement.  All
modules stay in the tree and in the build (`ZkFormal.V3.Integration`).

## 2026-10-13

### Tools (committed)

* `zk-formal/scripts/ClosureDeps.lean` — `lake env lean --run scripts/ClosureDeps.lean OUT
  Mod... -- const...`.  Walks the kernel dependency graph from root constants (type + value
  references, inductive ctors/recursors/mutual block, constructor → inductive, recursor → block,
  structure projections), maps constants to defining modules, and writes `modules.tsv`
  (needed / in import closure of needed), `refs.tsv` (per module: modules referenced by all of
  its constants, and by its needed constants only), `cuts.tsv`, `needed-consts.tsv`.
* `zk-formal/scripts/TypeHashes.lean` — fingerprints (`Expr.hash` of the type) of every
  `ZkFormal`/`ReexecV3D0` constant; used to check that no statement changed.
* `zk-formal/scripts/judge-time.py` — judge-style timing (pipeline.rs `compile()` for the candidate
  stage): serial plain `lean -R root -o X.olean -i X.ilean X.lean` (pinned toolchain binary, no
  lake, no `-D`, no C) per candidate module of the import closure, in dependency order, against
  warm trusted `.olean`s (ArenaCore / NearSpec / NearSpecV3), into a fresh output dir.
  `JT_SRC=<snapshot>` reads sources from a snapshot so the tree can be edited meanwhile.

All timings below are **single-core** (`taskset -c 10`, one `lean` at a time).  Lean 4.34
elaborates independent declarations of one module in parallel, so on a multi-core judge the
wall-clock is lower (the earlier HANDOVER estimate, ≈5,000–6,000 s, was multi-threaded:
e.g. `Render.Ups.GWalk` 86 s there vs 304 s single-core here).

### Step 2/3 — splitting needed lemmas out of modules that pull in heavy unneeded code

After step 1 every remaining unneeded module is reached only through the *unneeded*
declarations of some needed module.  For each heavy unneeded module X, the set of needed modules
whose unneeded constants reach X ("split points") was computed (scratch `splits.py` over
`refs.tsv` + baseline timings); splitting all of a group removes X.  Mechanism, per split point M:
the declarations of M the certificate needs move **verbatim** (same namespace, names, statements,
proofs) into a new module `<M>Core` (imports: the modules their constants reference; `open`s of
namespaces that do not exist there dropped), and M imports `<M>Core`, so every existing importer
still sees every name.  The planner of step 1 then redirects importers that need only the Core.

### Hot modules — proposals (not applied)

* **`Render.Codec{EndInt,RecInt,Header}` = 3,285 s, 38 % of the closure** (all needed).  Profile of
  `CodecHeader` (330 s): `simp` 216 s, kernel type checking 54 s, share-common-exprs 10 s, linting 7 s.
  The `codec_int` macro (`Render/CodecDefs.lean`) runs a ~150-lemma `simp only` (row tables
  `hdrA/recA/...`, `lookup`, `reg_0..31`, `hcur/hnxt`) on every constraint of every row case, then a
  16-way `first` cascade whose early `simp [*]` alternatives are expensive when they fail.  Pure proof
  refactors with identical statements: (1) pre-evaluate the row tables once per case into
  `@[simp] theorem` facts (`lookup (recA I R f g …) c 0 = …`) so the big `simp only` set shrinks to a few
  lemmas; (2) reorder / specialise the `first` cascade per constraint family (record which alternative
  closes which constraint index); (3) split each theorem's case analysis into per-case lemmas in separate
  modules — no CPU saving, but the judge then elaborates them in parallel (and the 1 h per-module cap
  stops depending on one 1,700 s module).
* **`Assembly.NearAirCheck` (54 s)**: kernel time 66 s profiled = `nearAirV3_wf` ~14 s +
  `nearAirV3_npOkPg` for g = 1, 2, 3 (~17 s each).  The certificate uses only `nearAirV3_npOkPg 2`
  (`NearAdmission.lean:44`).  Pure proof refactor: a `nearAirV3_npOkPg2 : NpOkPg nearAirV3 (pg 2)`
  lemma (plus `nearAirV3_wf`) in a small module imported by `NearAdmission` / `ExtractV3`, with
  `NearAirCheck` keeping `nearAirV3_npOkPg` (∀ g) from the g = 1, 3 cases and the g = 2 lemma;
  saves ≈ 35 s single-core.
* Remaining unneeded modules (≈ 400, ≈ 500 s estimated) sit behind many small split points
  (`Near.Link.Sha` 22, `Near.Render.Proof.NodeCells` 7, `ReexecV3D0.NormBytes` in the reference
  candidate); diminishing returns.

### Process notes

* Never interrupt `lake build`: a killed job can leave an `.olean` newer than its `.trace` that Lake
  later treats as up to date (it produced a bogus "unknown identifier" in a dependent once).  After
  an interruption, delete every `X.olean/.ilean/.trace` whose `.olean` is newer than its `.trace`.
* An unbounded `lake build` of ~5,400 targets ran ~10 `lean` processes at once and was OOM-killed
  in the 16 G scope; building in topological batches of 2 targets (`lake build A B`) is safe.
* While stopping that build I ran `pkill -x lake`, which matches every `lake` process of the user;
  no other lane's `lake` was running at the time as far as `ps` showed, but use PIDs.

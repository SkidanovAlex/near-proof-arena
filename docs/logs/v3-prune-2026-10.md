# Lane `lane/v3-prune` — certificate import-closure pruning, log

Worktree `/data/illia/nearproof-wt/v3-prune`, branch `lane/v3-prune`, from main `14ce4cde`.
Goal: shrink the import closure of the D0a certificate (`nearV3_admission_final`, packaged as
`NpUdrStarkV2.certificate`) without deleting code and without changing any statement.  All
modules stay in the tree and in the build (`ZkFormal.V3.Integration`).

## 2026-10-13

### Tools (committed)

* `zk-formal/scripts/ClosureDeps.lean` — `lake env lean --run scripts/ClosureDeps.lean OUT
  Mod... -- const...`.  Walks the kernel dependency graph from root constants (type + value
  references, inductive ctors/recursors/mutual block, constructor → inductive, recursor → block,
  structure projections), maps constants to defining modules, and writes `modules.tsv`
  (needed / in import closure of needed), `refs.tsv` (per module: modules referenced by all of
  its constants, and by its needed constants only), `cuts.tsv`, `needed-consts.tsv`.
* `zk-formal/scripts/TypeHashes.lean` — fingerprints (`Expr.hash` of the type) of every
  `ZkFormal`/`ReexecV3D0` constant; used to check that no statement changed.
* `zk-formal/scripts/judge-time.py` — judge-style timing (pipeline.rs `compile()` for the candidate
  stage): serial plain `lean -R root -o X.olean -i X.ilean X.lean` (pinned toolchain binary, no
  lake, no `-D`, no C) per candidate module of the import closure, in dependency order, against
  warm trusted `.olean`s (ArenaCore / NearSpec / NearSpecV3), into a fresh output dir.
  `JT_SRC=<snapshot>` reads sources from a snapshot so the tree can be edited meanwhile.

All timings below are **single-core** (`taskset -c 10`, one `lean` at a time).  Lean 4.34
elaborates independent declarations of one module in parallel, so on a multi-core judge the
wall-clock is lower (the earlier HANDOVER estimate, ≈5,000–6,000 s, was multi-threaded:
e.g. `Render.Ups.GWalk` 86 s there vs 304 s single-core here).

### Step 1 — import redirection (no declaration moved)

Planner (scratch, logic recorded here): R = closure of the roots under "modules referenced by any
constant of the module" (4,090 modules).  For every module in R, an import of a module outside R
is dropped and replaced by the minimal set of modules covering the kernel references of all of its
constants, plus a provider for every `open`ed namespace and every exported `syntax`/`macro`
keyword it uses; modules outside R that lost a transitive re-export get explicit imports to what
they reference (so every importer still compiles).  387 files edited (229 drop an import), plus

* `ZkFormal.V3.Integration` now also imports the 6 modules that are no longer reached through
  the certificate (`ReexecV3D0.NormalForm`, `Assembly.RcptReceiptRepaired`,
  `Assembly.RoutingCounterRanks`, `Candidates.CodecZeroTest`, `Rcpt.Candidates.NativeReplayConstructor`,
  `Render.Ups.MemRegisters`) — nothing is orphaned from the build;
* **import order matters for fragile `simp` proofs**: four modules (`DedupPartitionTraffic`,
  `SourceLog22Tables`, `DedupExtractRows`, `RcptSystemGasZero`) failed because the relative order
  of the `ZkFormal.Near.eval_*` simp lemmas (`Near/Extract/Eval.lean`) and later imports changed
  (bisected: importing `Extract.Eval` first restores it; same environment otherwise).  Fixed by
  importing `ZkFormal.Near.Extract.Eval` first in `Rcpt/Render/Srcp/Gen.lean` (the module whose
  old first import `Extract.Srcp.Proof` brought it early) and in `Assembly/RcptSystemGasZero.lean`.
  No proof was edited.
* 11 tests under `zk-formal/test` relied on transitive re-exports and now import the module that
  defines the audited constant.  Three tests fail identically on main `14ce4cde` with the original
  `.olean`s (checked): `AuditHonestBalanceRcpt`, `AuditRenderV3RcptTables` (constants
  `honest_src_balance` / `accepted_src_balance` no longer exist; only `_dd` variants) and
  `AuditPackedPublic` (`#guard` on the prepared-segment widths) — left untouched.

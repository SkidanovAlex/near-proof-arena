Benefit: prevent another expensive isolated gadget whose complete consumer cannot fit.

## Additional technical experiments, with uncertainty

These were not found as developed proposals in the reviewed process records; that is not a claim of novelty in the literature.

* **Typed verifier event program with partial evaluation.** Represent external input, checked/derived state, absorb, challenge and equality checks explicitly. Specialize fixed AIR/layout constants once, retaining their profile binding; never specialize prover-selected branches. This extends existing closed-derived-state work to a common executable/cost/formal boundary. First experiment: express only one existing stage and show exact transcript-event parity with the original, plus reject a changed external binding. Stop if the event layer cannot preserve challenge chronology or adds comparable compiler complexity. Potential benefit: expose which repeated work is derivable and generate the joint layout without three divergent hand implementations. No hash omissions or QROM theorem follow from event typing alone.

* **Separate fixed lookup relation work from witness multiplicity work.** Nibble tables already contain immutable truth rows, while multiplicities remain witness-dependent. Screen a transparent fixed polynomial/evaluation representation for the truth relation so the recursive statement authenticates only changing multiplicities/requests. First price fixed-table source, auxiliary, roots and opening costs separately; retain membership/link checks and account for setup constants/verifier data. If a sound fixed relation check costs at least what it replaces, stop. This differs from shortening multiplicity bit widths and from merely excluding the trusted spec from wire bytes. It is an uncertain architecture experiment, not permission to drop table commitments or assert preprocessing is free.

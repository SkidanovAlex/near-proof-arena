# Recursive compression experiment

Research harness for wrapping the existing np-udr-stark-v1 Rust reference verifier
in a RISC Zero succinct receipt. See
[`recursive-compression.md`](../../../docs/research/recursive-compression.md)
for security assumptions, v3 scope and interpretation of results.

Build with the installed RISC Zero guest toolchain (`rustup toolchain list` must
include `risc0`):

```sh
HEAVY_MEM=16G CARGO_TARGET_DIR="$PWD/target/recursion-compress" \
  CARGO_BUILD_JOBS=8 RUSTC_WRAPPER= taskset -c 8-15,24-31 \
  /data/illia/nearproof-deps/bin/heavy \
  cargo build --release --locked --manifest-path tools/recursion/compress/Cargo.toml \
  -p compression-host
```

The workspace and guest have separate lockfiles. The verifier adapter imports
repository source directly; changes to those files change the guest image ID.
The host uses an explicit local `r0vm` subprocess, never a remote service. Set
`RISC0_SERVER_PATH` to the installed RISC Zero 3.0.6 executable. For this host:

```sh
export RISC0_SERVER_PATH=/home/illia/.risc0/extensions/v3.0.6-cargo-risczero-x86_64-unknown-linux-gnu/r0vm
```

Every execution defaults to a 256 × 2^20 cycle ceiling; set
`COMPRESSION_MAX_CYCLES` explicitly for a larger execution-only measurement.
Use an external wall-time and memory bound as well.

The executable takes six arguments:

```
compression-host ACTION AIR_JSON PUBLIC_TAPE CLAIM INNER_PROOF RECEIPT
```

Actions:

- `native`: run the Rust reference verifier and emit input identity/timing JSON.
- `execute`: run native verification, then execute the guest and compare journals.
- `reject`: require native rejection and guest failure specifically reporting
  `inner proof rejected`; resource errors do not count as successful rejection.
- `succinct`: generate a real recursive receipt, check it and four outer
  mutations, then save it. Existing receipt files are not overwritten.
- `verify`: verify a saved succinct receipt against the compiled image ID and the
  independently expected AIR/public tape/claim. The inner-proof argument is
  ignored: the inner proof is not needed for verification.

Example from the repository root, with a fixture directory containing `air.json`,
`pub.bin`, `claim.bin`, `proof.bin`:

```sh
RAYON_NUM_THREADS=8 HEAVY_MEM=16G taskset -c 8-15,24-31 \
  /data/illia/nearproof-deps/bin/heavy /usr/bin/time -v timeout 600 \
  target/recursion-compress/release/compression-host execute \
  FIXTURE/air.json FIXTURE/pub.bin FIXTURE/claim.bin FIXTURE/proof.bin RECEIPT.bin
```

Use `succinct` after inspecting execution cycles. The reported receipt size
includes the journal and bincode framing, but excludes independently available
public statement/context bytes. Count any separately transported claim bytes
when assessing a complete network message. The journal binds an AIR digest; a
production verifier must pin the expected AIR and public artifact independently
of the prover. This prototype does not implement v3 hint preprocessing.

`RISC0_DEV_MODE` must be absent or `0`; the host also enables `disable-dev-mode`.
The verifier requires the `Succinct`
receipt variant. Any fake receipt, wrong guest image or mismatched journal is
rejected. Native rejection alone is not evidence of guest rejection; use the
`reject` action for the latter.

The included `fixtures/tiny` proof was generated by
`r1calib seg 1 4 1 --k 1`; it passes the Rust and prebuilt Lean verifiers.
Run and retain logs, input hashes, peak RSS and JSON results with:

```sh
python3 tools/recursion/compress/run.py execute \
  tools/recursion/compress/fixtures/tiny target/compression-tiny-check
```

The output directory must not already exist. `run.py` distinguishes cycle and
wall-time limits from verifier rejection. `verify` also runs four outer negative
checks without reproving. Results under `results/2026-10-14` include the initial
cycle-limit runs as well as the successful measurements with a higher ceiling.
